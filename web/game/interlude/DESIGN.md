# 幕间四部 ·《第七位观察者》设计说明

首章之后这一段（`ch1` 幕间）的完整设计文档。四幕合起来是一条闭环：**每一幕的玩法产出一个结论，这个结论是下一幕的入口；四幕走完，玩家亲手定稿第 8 行。**

- 版本 `2.0.0`，chapter 命名空间 `ch1`（只是命名空间，不改 `save.chapter`，原版仍停在 `ch0`）
- 章节标识：`act1.*` ~ `act4.*`（不推 `ch1` 章节指令，不碰原版 `ch0` 的任何 flag）
- 规模：**4 幕 / 25 个剧情节点 / 161 句台词 / 约 18–20 分钟 / 4 种新玩法**（纯阅读约 8.7 分钟，四道解谜操作约 10 分钟）
- 前置：`ch0.done`（首章任一结局之后）
- 文件：`ch1_a1.js` `ch1_a2.js` `ch1_a3.js` `ch1_a4.js`（各一幕）+ `index.js`（汇总登记）
- 校验：`node web/game/interlude/story-check.mjs`

---

## 1. 它接在原版的哪里

原版首章《消失的第零页》留下一个空档：第 8 行编号 000 的位置被空白覆盖，庭务说"这一行本该有内容"。首章的两个结局（归档原始记录 / 保留修订版本）都**只是处置了那一页纸，没有回答那一行本来该是谁**。

幕间从这里接：**编号 000 按规则属于「观测者」，而观测者只有一个。** 玩家自己就是观测者——那么记录里那个空位，是被谁占着？

四幕不需要新地图、新战斗、新美术，全部发生在观测站 / 档案厅 / 长廊 / 温室的既有场景里（复用 `bg_*` 与既有 NPC）。这是刻意的：幕间是"加在既有场景上的一段推理"，不是新关卡。

## 2. 叙事主线（一句话版）

> 那一行不是被抹掉的，是**每一序列都换一个人站上去**的；而换人的手续，这一次没走完。

四幕各推进一步：

| 幕 | 玩家做的事 | 得到的结论 |
| --- | --- | --- |
| 一 | 把四列读数摆回第 8 行 | 那四列确实属于观测者，而观测者只有一位 |
| 二 | 对照今晨与五年前的两份留存 | 十二个位置从没同时出现过十二个名字——不是删，是轮流换 |
| 三 | 把被摘走的第五条规则接回去 | 覆盖观测者须经本人同意；**你的那一份没有签字** |
| 四 | 亲手决定第 8 行由谁站着 | 你不再追问它是谁，你替它定稿 |

## 3. 逐幕结构

### 幕间一《第七位观察者》— 推演台 `ledger`

```
m1_intro（7 句，庭务摆开推演台）
  └─ [推演台] 4 列格 · 6 张证据卡
       ├─ 无误差 → m1_outro_clean（5 句）
       └─ 有误差 → m1_outro_fuzzy（4 句）
            └─ m1_verdict（二选一）
                 ├─ m1_end_write（写下这一行）→ roster_copy
                 └─ m1_end_blank（留空只写批注）→ blank_row
                      └─ "——幕间一完。" → m2_intro
```

**设计要点**：误差不判失败，只决定收束对白是 clean 还是 fuzzy——fuzzy 分支里庭务会说"被改过的记录，从来不假装自己没被改过"。这是本作"温柔悬疑"基调的关键：**系统不惩罚玩家，只让世界观记住玩家的痕迹**。

### 幕间二《两个版本》— 对照台 `ledger_cmp`

```
m2_intro（笺摊开两份卷宗：今晨留存 / 五年前留存）
  └─ [对照台] 12 行并排，标出 5 处出入 → 末行确认
       ├─ 无误差 → m2_outro_clean
       └─ 有误差 → m2_outro_fuzzy
            └─ m2_reveal（「十二个位置从来没有同时出现过十二个名字」）
                 ├─ m2_ask_now（第 8 行现在站着谁）
                 └─ m2_ask_know（换上去的人自己知道吗）
                      └─ m2_bridge（瑾：名册不是名册，是座位表）
                           └─ "——幕间二完。" → m3_intro
```

**核心理念**：五项出入里有两项是**同一个人、名次对调**（渡 百名内→前五十 / 钤 前五十→百名内）——玩家标到最后会察觉"这不是改错，这是两个人在交换位置"。台词「十二个位置从来没有同时出现过十二个名字」是这一幕的题眼。

设问分支给的答案（两句都通向同一个 bridge）：
- 现在站着谁 → 「以前每一次覆盖，都是把一个人换上去。这一次，是把人拿下来了，没放新的」「拿下来的人还在这栋楼里——不然你的铭牌不会是空的」
- 换上去的人自己知道吗 → 「前四位，都不知道」「他们每一个，都在换上去之后的第七天来问我同一个问题：『我是不是少了七年。』」

### 幕间三《排序的代价》— 编排台 `ledger_rule`

```
m3_intro（长廊尽头规则墙，第五条铜牌被摘下重装）
  └─ [编排台] 5 条残片按序接回（附录是干扰项）
       ├─ 无误差 → m3_outro_clean
       └─ 有误差 → m3_outro_fuzzy
            └─ m3_sig（第五条：如覆盖对象为观测者，须经其本人同意）→ rule_wall
                 └─ m3_bridge（绢：第十四号苗床）
                      └─ "——幕间三完。" → m4_intro
```

**核心理念**：推理片里最硬的证据不是目击者，是**流程记录**。第五条被拧下来过，螺丝是反着拧的——所以"这次覆盖"不是权限问题，是**手续没走完**。瑾的扇骨内侧抄着十年前的全文，扇骨最末压着四个被反复描过的字：「留一格空」。

配合第四条（编号 000 不参与排位）推出：**第 8 行本来就是留给「不参与排位的人」的**。

### 幕间四《十二分之一》— 定稿台 `ledger_final`

```
m4_intro（温室第十四号苗床下的铁盒："第零页 · 观测者 · 备用方案"）
  └─ m4_pick（庭务推来定稿台：第四条与第五条同时生效，本庭务无权替你决定）
       └─ [定稿台] 12 个名字选一个填第 8 行 → 四选一处置
            ├─ m4_end_write  写下别人的名字 → signed_row
            ├─ m4_end_blank  让它继续空着   → empty_eighth
            ├─ m4_end_self   写下自己的名字 → own_name
            └─ m4_end_open   交给庭务       → open_case
                 └─ m4_coda（附记）→ "——第一章附记完。"
```

**核心理念**：**没有正确解**，四个处置都算通关。定稿台不评判玩家，它只把"最后一格"交到玩家手上。附记回到观测站：休眠舱玻璃上的手印，「第一次对上，是巧合。第二次对上，是习惯。到第几次，才算是你自己？」最后庭务说出「第七序列第五位观测者在场」——**这是庭务第一次说出一个编号**。

## 4. 四种玩法形态

四幕各一种玩法，共同点是：**都是核实/编排，不是战斗**；都零新美术（纯 `R.text/R.box` + 既有配色）；都无失败态（可计数，但不清零、不消耗、不判负）；`Esc` 随时退出、进度保留。

### 4.1 推演台（`ledger`）— 幕一

把 6 张证据卡放进 4 个列格，每个列格只认一张卡。

```
┌────────┬────────┬────────┬────────┐
│ 编号   │ 条目   │ 读数   │ 分档   │   ← 目标：000 / 观测者 /（空）/ 榜外
└────────┴────────┴────────┴────────┘
┌──────────────────┬──────────────────┐
│ 编号             │ 条目             │
├──────────────────┼──────────────────┤
│ 读数             │ 分档             │
├──────────────────┼──────────────────┤
│ 时间（干扰）      │ 归属（干扰）      │   ← 6 张手牌
└──────────────────┴──────────────────┘
```

- 正确 4 张：`c_no` / `c_name` / `c_read` / `c_band`；干扰 2 张：`c_time`（05:12 是覆盖时刻，不是这一行的内容）、`c_who`（庭务是记录者，不是被记录者）。
- 每张卡自带推理线索：编号卡说"覆盖发生过四次，四次都写回同一个编号"；读数卡说"覆盖时读数被一起吃掉了"——**读卡就能推出来**，不用暴力枚举。
- 操作：`←→↑↓` 切列 / `空格` 选列 → 选卡 → `空格` 放置；`Esc` 离开或取消选卡。
- 反馈：摆对→列格落定、自动跳下一空列；摆错→右下红字"这一张对不上这一列 · 误差 N"，卡还在手上、列格仍空；四列填满→立刻收束。

### 4.2 对照台（`ledger_cmp`）— 幕二

12 行名册左右并排，左边"今晨留存"、右边"五年前留存"，玩家逐行标记出入。

- 数据：`PUZZLE.rows = [{id, no, left, right, diff, note}]`，`diff:true` 的 5 行是答案。
- 操作：`↑↓` 移动行光标 / `空格` 标记或取消 / 末行「确认」提交。
- 反馈：标记正确时该行高亮，标记错误时提示"这一行两份一致"；全部标对且无多标 → `clean`。
- 设计意图：让玩家用眼睛做 diff，而不是被告知结论。**"同一人上下对调"那两行是必须亲眼看见的**。
- 写作约束：`diff:true` 的两侧文字**必须在字形上真的不同**（字距/空格差异都写进字符串），否则玩家无法用眼睛发现，`story-check` 也会报错。

### 4.3 编排台（`ledger_rule`）— 幕三

左边规则墙有 5 个空位（按 `ord` 1..5），右边手牌是 6 张残片，其中 1 张是「附录」干扰项。

- 数据：`PUZZLE.cards = [{id, ord, text, clue}]`，`ord:0` 的附录不是条文。
- 操作：`↑↓` 选残片 / `←→` 移到想填的位 / `空格` 放上去；`Esc` 撤回或退出。
- 反馈：接对→空位填上；接错→"附录不是条文 · 误差 N"（附录）或"顺序不对 · 误差 N"（错位），卡回到手上。
- 设计意图：**顺序**本身就是推理内容——第五条必须在第四条之后，因为它引用第四条。

### 4.4 定稿台（`ledger_final`）— 幕四

两个阶段：先从 12 个名字里选一个填进第 8 行（名字网格 4 列 × 3 行），再从 4 个处置里选一个（写 / 空 / 自己 / 交还）。

- 数据：`PUZZLE.names = [{id, name, alias, note}]`（alias/note 直接取 `GD.roster` 的原文设定）、`PUZZLE.options`。
- 操作：`↑↓←→` 选名字 / `空格` 定为；然后 `↑↓` 选处置 / `空格` 定稿；`Esc` 返回改名字。
- 反馈：第 8 行在上方名册里高亮，选定名字立刻显示"000 · 闸 · 限流者"；定稿后立刻播对应结局对白。
- 设计意图：**这是整段里唯一"不可撤销"的动作**，但依然不评判。选定名字不决定结局，处置方式才决定结局。

## 5. 数据驱动：换一套题就是另一道解谜

四道玩法都是纯数据驱动，`PUZZLE` 结构与渲染/输入解耦：

| 玩法 | 数据集 | 换题方式 |
| --- | --- | --- |
| 推演台 | `cells[] + cards[]` | 换 4 列 6 卡 |
| 对照台 | `rows[]（含 diff 标记）` | 换 12 行差异 |
| 编排台 | `cards[]（含 ord/clue）` | 换条文与顺序 |
| 定稿台 | `names[] + options[]` | 换候选与处置 |

`story-check.mjs` 会校验每道题的 `PUZZLE` 自洽（正确项唯一、干扰项不在答案集、`ord` 连续无重复）。

## 6. 存档

存在 `save.interlude.ch1`，按幕分四个子空间：

```js
{
  a1: { active, solved, errors, placed:{cellId:cardId}, hand:[], verdict, runs },
  a2: { active, solved, marks:{rowNo:1}, found:[], verdict, runs },
  a3: { active, solved, chain:[cardId...], hand:[], errors, verdict, runs },
  a4: { active, solved, picked, choice, verdict, runs }
}
```

- 幕进度按 **`doneFlag` 是否已写**判定（不是 `solved`）——玩法推完但收束对白还没播完，不算过幕，中途退出不会被后续幕抢先解锁。幕四例外：`doneFlag` 之后还有附记 `m4_coda`，整幕真正结束以 **`endFlag: 'act4.coda'`** 为准，否则「结局对白播完、附记还没播」时退出会永远看不到附记。
- **断点续播**：每幕的 `start()` 以 flag 为准逐段续播——开场未播完→重播开场；玩法未推完→直接回玩法（已摆的列/已标的行都在存档里）；收束对白未播完→重播收束；设问/签名未做→回设问/签名；桥段未播→回桥段。不重播整段、也不跳过内容。
- **连播**：幕与幕之间用对白 `next` 直接相连（`m1_end_*` → `m2_intro`、`m2_bridge` → `m3_intro`、`m3_bridge` → `m4_intro`），四幕一口气播完，不需要回标题页重新按空格。
- 老存档（完全没有 `save.interlude`）由 `state.js` 的 `migrate()` + `Interlude.migrate()` 补齐。
- 重播结局不重复发道具：`item` 指令幂等（`if ((items[id]||0) < n) items[id] = n`）。

## 8. 通用设计约束（对主项目的可移植性）

- **零新美术**：四种玩法全部用 `R.text / R.box / R.bar` + 既有配色（`COL.paper/dark/ink/zhu/dian/jin/mut`）。这也是它能在不依赖 pixel-artist 的情况下交付的原因。
- **不阻塞主线**：`Esc` 随时退出，进度落存档，下次进来接着做。
- **无失败态**：误差只累加不清零、不消耗资源、不结束。"解不开"不会卡住玩家，最坏情况是退出再进。
- **不使用 `{op:'chapter'}`**：幕间的 chapter 名 `ch1` 只是命名空间，不推章节、不做次章预告（符合原版"首章止于 ch0"的硬约束）。
- **旁白第二人称、无性别代词**，和原版一致；对白 `who` 用显示名（庭务 / 你 / 汐 / 瑾 / 绢 / 楷），不用角色 id。

## 9. 评审入口

想直接看四幕，不用通关首章：URL 加 `?interlude=1`。

```
file:///…/web/game/index.html?interlude=1
```

预览只跳过**章节闸门**，四幕顺序、玩法、结局分支全部照常；四幕都走完后标题页空格交回原版。

## 10. 后续可扩展的方向（留给主项目决定）

- **玩法系列化**：四道题都是数据驱动的，换 `PUZZLE` 就能出"第 9 行 / 下一序列"的可选支线，做成收集。
- **误差的后果化**：现在误差只影响对白语气与 verdict，可以升级成"批注出现在后续章节的记录里"，让玩家的手滑变成世界观的一部分。
- **第七位观察者的身份**：这段刻意不揭示，只留"另一位在下一行的空白里"。要不要在后续章节收线，由主项目定。
- **四结局的差异回写**：`signed_row / empty_eighth / own_name / open_case` 四个道具目前只是纪念物，可以作为后续章节的分歧开关（例如 `own_name` 让玩家在次章拥有编号）。

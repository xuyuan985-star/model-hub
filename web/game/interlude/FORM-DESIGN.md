# 游玩形式设计 · 从"战斗驱动"到"核实驱动"

这份文档回答一个问题：**这个游戏"以什么形式进行游玩"**。它不描述某一幕的具体剧情（那是 `DESIGN.md`），而是给主项目负责人一份可讨论、可选型、且**已经跑通验证**的方案。

> 状态：A 形态已实现并扩展成四种玩法，落在 `web/game/interlude/`（4 幕 / 25 节点 / 161 句 / 约 18–20 分钟）。

---

## 1. 原版形态盘点

原版首章的玩法骨架是：**走格子探索 → 撞怪进回合制战斗 → 打完抽卡/打卡 → 推进剧情**。

| 环节 | 原版做法 | 承担的作用 | 问题 |
| --- | --- | --- | --- |
| 探索 | 24×14 格子、5 张图、33 个交互点 | 给"主线 20 分钟"打拍子 | 地图只当传送带，格子本身不产生决策 |
| 战斗 | 回合制，hp/slots/quota 三轴、12 个技能 | 把"模型能力"具象成数值 | 与叙事零耦合：打赢吞页兽和"第零页被覆盖"没有关系 |
| 抽卡 | 5★ 0.6% 硬保 90、UP 池 | 长线留存 | 首章是 20 分钟体验，抽卡在这里没有落点 |
| 打卡 | 7 天循环、免费货币 | 日活 | 同上，单章体验里用不到 |

**结构上的空缺**：世界观的冲突是"**记录被覆盖、名册少了人**"——这是个信息/证据类的悬念，但玩家解决它的方式是**打赢一只怪物**。形式与内容错位了。

## 2. 可选形态清单

给主项目做选择题。每种形态都标了它适配什么、代价是什么。

### A. 核实驱动（recommended，已实现为四道题）

玩家收集证据，把结论**摆出来**——摆进表格、对上编号、指定归属、按序复位。

- 适配：本作的核心悬念（榜单被覆盖、名册缺人、编号 000）。
- 优点：与叙事同构；零新美术（纯 UI 渲染）；可数据驱动批量出题；没有失败态就能天然贴合"温柔悬疑"基调。
- 代价：单题时长有限（2–5 分钟），需要靠"多行/多序列"扩展成系列。
- **已验证**：`interlude/` 里四幕各一种题型，共用一个运行时，见下表。

| 幕 | 题型 | 玩家动作 | 认知负荷 |
| --- | --- | --- | --- |
| 一 | 推演台 `ledger` | 6 张卡 → 4 个列格 | 分类/归属：这一列该填什么 |
| 二 | 对照台 `ledger_cmp` | 12 行并排，标出 5 处差异 | 比对：两份记录哪里不一样 |
| 三 | 编排台 `ledger_rule` | 5 条残片按序复位（1 张附录干扰） | 排序：条文的先后依赖 |
| 四 | 定稿台 `ledger_final` | 12 选 1 填格 + 4 选 1 处置 | 决策：无正确答案，只有立场 |

四种题型刻意不一样，是因为**同一套动作重复四次会变成作业**；但它们共用同一套渲染原语（`R.text/R.box`）与同一套"误差计数、不判负"的反馈语言，所以玩家学一次就会。

### B. 对照驱动（diff / 版本回滚）— **已作为幕二落地**

把"被覆盖前"和"被覆盖后"两份记录并排，玩家标出差异、决定保留哪一版。

- 适配：首章已经有两个结局（归档原始记录 / 保留修订版本），形式可以更彻底——让玩家**在多个版本间来回对照**。
- 优点：天然复用"双写""版本"这些机制名词；可以做成分屏 UI。
- 代价：需要更多文本内容做"差异"，工作量在写作侧。
- **实践结论**：写作成本确实是最高的，但**收益也最高**——"同一个名字在两份卷宗里排在不同行"这一句，只有玩家自己 diff 出来才有说服力。写作技巧是把差异控制在"能被眼睛抓住"的尺度：档位变化、字距变化、册页毛边。

### C. 编排驱动（把战斗改成"组队跑一次任务"）

保留回合制骨架，但把胜负条件从"打空血条"换成"**在预算内把任务做完**"——算力配额（quota）成为真正的资源，遗忘（slots）成为真正的代价。

- 适配：三轴（hp/slots/quota）本来就是富矿，现在只用到了 hp。
- 优点：改动量最小（战斗层已实现），叙事耦合度立刻提升；"技能 cost ≤ 该角色 quota 的一半"这类约束能变成真决策。
- 代价：需要重调平衡，且仍然没有回答"证据从哪来"。
- **现状**：**未实现**。这是留给后续章节的方向，因为它要改原版战斗层，风险和收益都更大。

### D. 档案驱动（元游戏：经营一座观测站）

玩家不是"打"，是**整理**：归档、编目、补页。

- 适配：世界观已经叫"观测站/档案厅/庭务"。
- 优点：与"记录"母题最贴；可以做成长期玩法（每日归档）。
- 代价：离"20 分钟冒险"较远，更像另一个游戏。
- **现状**：**未实现**。可以作为 A 的长期化升级路径（把四道题变成每日轮换的归档任务）。

## 3. 选定：A 为主，C 为辅

**理由**（三条，按权重）：

1. **同构**。本作的核心动词是"记录/覆盖/归档"，那么玩家最该做的动作就是"核实"。A 让动词对齐：玩家在游戏里做的和剧情里发生的是同一件事。
2. **成本**。A 是纯 UI + 数据，没有任何新美术依赖。角色美术还在攻坚，A 可以完全不等美术就上线。**四道题全部落地后，美术零新增依赖依然成立**——这是它最大的工程优势。
3. **不冲突**。A 作为"幕间"插在章节之间，不替换原版探索/战斗，主项目不需要做取舍——它是**加法**。C 可以作为后续把战斗改造成"预算内完成任务"的方向，但那属于改原版，风险高，建议放到后续章节。

**不选 B/D 作主形态的原因**：B 的写作成本压在你们身上（要产出多版本全文），D 的工期不可控（等于另一个项目）。但 B 已经被吸收成 A 的一种题型（幕二），所以不是"放弃"而是"合并"。

## 4. 为什么"无失败态"是形式设计的核心

原版战斗有死亡、有战败回滚。但本作基调是"温柔悬疑 + 轻冒险（非黑暗末世）"。A 形态里：

- 摆错只记一个"误差"，不清零、不消耗、不结束；
- 误差只影响收束对白的语气（clean / fuzzy），不判好坏；
- `Esc` 随时退出，进度保留，下次进来接着做。

这不是"降低难度"，而是**让系统的态度和世界观的态度一致**：智械庭不惩罚记录者，它只是把改过的痕迹留在纸上。玩家在 fuzzy 分支听到庭务说"被改过的记录，从来不假装自己没被改过"，这句话就是玩法形式本身在说话。

四幕一致地执行了这条：**幕四甚至没有正确答案**——四个处置（写下别人的名字 / 留空 / 写下自己的名字 / 交给庭务）都算通关，只是拿到不同的纪念物。这是形式层面对"智械庭从不替你决定"的呼应。

## 5. 形式如何扩展成系列（给主项目留的接口）

四种题型都是纯数据驱动，渲染与输入和题目解耦：

```js
// 推演台
PUZZLE = { cells: [{id, col, need, value}], cards: [{id, key, text}] }

// 对照台
PUZZLE = { leftName, rightName, rows: [{id, no, left, right, diff, note}] }

// 编排台
PUZZLE = { wall, cards: [{id, ord, text, clue}] }   // ord:0 = 干扰项

// 定稿台
PUZZLE = { names: [{id, name, alias, note}], options: [{id, text, hint}] }
```

- 想出"第 9 行/第 10 行"，只加一份 `PUZZLE` 数据 + 一段收束对白。
- 想让误差产生后果：把 `errors` 写进一个 flag，后续章节读它决定对白分支。
- 想换题型：渲染层每道 60–100 行，加一个新题型是"再加一个 `mode`"，运行时不用动。
- 想复用给别的章节：四道题的模式 id 是通用的（`ledger*`），换个 `nsKey` 和 `nodes` 就是另一段幕间。

## 6. 一句话交接

> 叙事负责"记录被谁改的"，玩法负责"让玩家亲手把记录拼回去"。两者是同一件事，所以不需要用战斗来过渡。

四道题是这个论点的四种证法：**分类填格**（幕一，那是谁）→ **并排比对**（幕二，改过几次）→ **按序复位**（幕三，凭什么改）→ **亲手定稿**（幕四，谁来决定）。
